# Бюджет — 50 / 30 / 20

Личный трекер бюджета по методу 50/30/20 (Сбер / Альфа / Озон). React + Vite,
устанавливается как PWA (иконка на телефоне). Данные хранятся в облаке
**Supabase** (вход по почте и паролю), поэтому одни и те же записи доступны
на всех ваших устройствах. Копия данных кэшируется в `localStorage`, так что
приложение открывается и без интернета, а изменения, сделанные офлайн,
отправляются, когда сеть появится.

## Быстрый старт (локально)

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`.

## Как устроены данные

- Таблица `app_data` в Supabase: `user_id`, `key`, `value`, `updated_at`.
  В ней два ключа на пользователя: `settings` и `transactions` (JSON).
- Запись «условная»: если те же данные успели изменить на другом устройстве,
  старая версия их не затрёт — приложение покажет плашку «обновить».
- Доступ к строкам ограничен правилами RLS: каждый видит только свои данные.

## Настройка Supabase

1. В проекте Supabase создайте таблицу `app_data` с колонками `user_id uuid`,
   `key text`, `value text`, `updated_at timestamptz` и составным первичным
   ключом `(user_id, key)`.
2. Откройте **SQL Editor**, вставьте содержимое файла
   [`supabase-security.sql`](./supabase-security.sql) и нажмите **Run** — это
   включит RLS и создаст правила доступа.
3. Адрес проекта и публичный (publishable) ключ прописаны в `src/storage.js`.
   Публичный ключ можно хранить в коде: защита данных обеспечивается RLS.
4. Если приложением пользуетесь только вы, отключите регистрацию новых
   пользователей: **Authentication → Sign In / Providers → Email → Allow new
   users to sign up** (после того, как создадите свою учётную запись).

## Совместный бюджет (режим двоих)

Для двух человек с общими данными: операции, настройки, цели и платежи общие, правки обоих видны
у обоих.

1. В Supabase → SQL Editor выполните [`supabase-household.sql`](./supabase-household.sql).
2. Первый человек: **Настройки → Совместный бюджет → Создать и получить код**. Ваши нынешние
   данные копируются в общий бюджет (личные остаются как были).
3. Второй человек (со своим аккаунтом): **Войти по коду партнёра**. Он начнёт работать с общими
   данными; его личные данные не меняются и вернутся при выходе.
4. Доступ: общие данные видят и меняют только двое участников (правила RLS). В бюджете не может быть
   больше двух человек, код видит только владелец и может выпустить новый.
5. Если оба правят одновременно, правки сливаются (добавленное складывается, удаление и изменение
   не теряются), а у партнёра данные подтягиваются сами (при запуске, при возвращении в
   приложение и раз в 30 секунд). Чужие правки, сделанные пока вы были без интернета, тоже
   сливаются, а не затираются.
6. Выйти можно с копией общих данных (они заменят ваши прежние личные) или без неё.
   Если выходит последний участник, общий бюджет удаляется.

Фото чеков при создании бюджета переносятся в общий. В резервную копию JSON они не входят.

## Калькулятор и фото чека

- Под полем суммы есть кнопки `+ − × ÷ =`: на телефонах цифровая клавиатура не даёт ввести знаки.
  Можно набрать `1200+350`, под полем сразу видно результат, а `=` подставляет его в поле.
- В форме траты можно добавить фото чека (камера или галерея). Фото сжимается (до 1280 px),
  хранится в облаке отдельной записью `receipt:<id операции>` и не кэшируется на телефоне.
  В истории у такой операции появляется скрепка, по нажатию открывается фото. Для загрузки и
  просмотра нужен интернет. В резервную копию JSON фото не входят.

## Регулярные платежи и уведомления

- **Настройки → Регулярные платежи**: название, сумма, день месяца, бюджет и категория.
  Платёж не создаёт трату сам: в свой день он появляется в разделе «Платежи» на вкладке
  «Анализ» и в заметках, и вы нажимаете «Провести» (так цифры не меняются без вашего ведома).
- **Уведомления** включаются кнопкой в этом же разделе (или на экране «Анализ», пока они выключены).
  - Срочное: платёж сегодня, завтра или просроченный, и день выплаты. Приходит при открытии приложения.
  - Заметки (прогноз до аванса, сравнение месяцев, долги, перерасход, запас сбережений, советы) раньше
    были каруселью на экране «Анализ», теперь приходят уведомлениями в течение дня: не больше пяти
    в сутки, по одной в 9:00, 12:00, 15:00, 18:00 и 20:00, сначала самое срочное, в конце дня совет.
    Заметки про запас сбережений приходят раз в неделю. Если слот прошёл, а приложение было
    закрыто, заметка придёт при следующем открытии (не больше двух за раз).
  - Уведомления приходят, пока приложение открыто или свёрнуто (при запуске, при возвращении в него
    и раз в 10 минут). Когда оно полностью закрыто, телефон их не покажет: для этого нужен
    серверный push.

## Резервная копия

В **Настройки → Данные**:

- **Резервная копия (JSON)** — все настройки и операции одним файлом;
- **Таблица (CSV)** — операции для Excel (разделитель «;», UTF-8);
- **Восстановить из копии** — загрузить ранее сохранённый JSON (текущие данные
  заменяются после подтверждения).

## Публикация на GitHub Pages

1. В **Settings → Pages** репозитория выберите **Source: GitHub Actions**.
2. При каждом `git push` в `main` workflow `.github/workflows/deploy.yml`
   собирает проект и публикует его. Через 1–2 минуты сайт доступен по адресу
   `https://ВАШ_ЛОГИН.github.io/ВАШ_РЕПОЗИТОРИЙ/`.

## Установка на телефон

- **Android (Chrome):** меню (⋮) → «Установить приложение».
- **iPhone (Safari):** «Поделиться» → «На экран «Домой»».

## Структура проекта

Все файлы лежат в `src/` одной папкой (так их проще загружать через сайт GitHub).

```
src/
  App.jsx          — корневой компонент: загрузка/сохранение данных, навигация
  constants.js     — цвета, значки, настройки по умолчанию, списки и константы
  storage.js       — облачное хранилище на Supabase: вход, кэш, офлайн-очередь
  main.jsx, index.css — точка входа React, Tailwind и шрифты
  format.js        — даты, деньги, названия бюджетов и карт, склонение
  debts.js         — внутренние долги между бюджетами и их погашение
  finance.js       — балансы, итоги месяца, накопительное распределение, статистика
  insights.js      — заметки и подсказки для карусели, прогноз «на сколько хватит»
  forecast.js      — прогноз до аванса и сравнение расходов с прошлыми месяцами
  savings.js       — динамика сбережений, дата достижения цели, цели-копилки
  migrate.js       — приведение старых данных к текущему формату
  backup.js        — экспорт в JSON/CSV
  ui.jsx, cards.jsx, charts.jsx, panels.jsx, form.jsx, TabBar.jsx — компоненты
  AnalysisView.jsx, SettingsView.jsx, AuthScreen.jsx — экраны
  ForecastPanel.jsx — панели «Прогноз до аванса» и «Сравнение с прошлыми месяцами»
  SavingsPanel.jsx — график роста сбережений и панель целей
  recurring.js     — регулярные платежи: расчёт «пора провести», создание траты
  notify.js        — уведомления на устройстве: платежи, день выплаты, заметки в течение дня
  NotifyNudge.jsx  — предложение включить уведомления на экране «Анализ»
  receipts.js, ReceiptViewer.jsx — фото чеков: сжатие, сохранение в облаке, просмотр
  merge.js         — слияние одновременных правок двух людей/устройств
  HouseholdSettings.jsx — экран «Совместный бюджет» в настройках
  RecurringPanel.jsx, RecurringSettings.jsx — панель «Платежи» и настройка платежей/уведомлений
  AppStyles.jsx    — все стили приложения
supabase-security.sql        — правила RLS для таблицы app_data
supabase-household.sql       — таблицы, правила и функции совместного бюджета
.github/workflows/deploy.yml — автосборка и публикация на GitHub Pages
```
